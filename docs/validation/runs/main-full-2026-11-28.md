## What this run does not cover

- **macOS x64.** There is no such job and no such machine; `macos-latest` is arm64. Nothing may claim
  Intel macOS on the strength of this record.
- **The intermittent `STATUS_ACCESS_VIOLATION`.** It did not occur in this run — which is what
  "intermittent" means, and is *not* evidence that it is fixed. It remains open as #21, with the
  mechanism (node-pty 1.1.0's unsynchronised `ptyHandles`) and the observed rate recorded there.
- **The stress and endurance harnesses.** `npm run stress:assert` is a benchmark, not part of `npm
  test`; its phase D breach (`childrenSurviving`, ~1 run in 3) is recorded on #24.
- **Linux and Windows x64.** CI covers `ubuntu-latest`, `ubuntu-24.04-arm`, `windows-latest` and
  `windows-11-arm`; this record is one machine and does not substitute for those cells.

## Reproduce

```bash
git checkout adefc01
npm ci                      # postinstall applies both node-pty patches
npm run test:unit
npm run test:native
npm run test:server
npm run test:fault
npm run test:desktop
dotnet run --project clients/dotnet/Sentiora.ContractCheck -- .
```

`npm ci` must not be skipped: on a tree where the postinstall did not run, `test:server`'s WIN-24 and
WIN-26 fail by design, because they are the tripwires for exactly that.
